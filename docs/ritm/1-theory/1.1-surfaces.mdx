# Поверхности

Чтобы понимать, как использовать цвета и где какой цвет находится, введены понятия поверхностей, благодаря чему весь интерфейс можно построить с помощью трех поверхностей. Их два вида статические и динамические.

## Foundation

Это любой фон, статическая поверхность.

Пример: фон всей страницы, сайдбар, хедер и тд.

![Пример Foundation поверхностей](/media/telegram-cloud-document-2-5291759145895103513.jpg)

Пример Foundation поверхностей.

## Control

Интерактивный элемент с которым можно взаимодействовать мышкой, клавиатурой или скрин-ридером. При hover, active, focus, disabled меняет цвет, а также цвет текста на этой поверхности. Пример: кнопка, чекбокс, тогл, радио и тп.

![Пример Control поверхностей](/media/telegram-cloud-document-2-5291759145895103542.jpg)

Пример Control поверхностей.

## Wrapper

Сложный составной интерактивный элемент, также меняет цвет при взаимодействии в котором могут находится другие интерактивные компоненты.

Пример: инпут, текстареа, карточка.

![Пример Wrapper поверхностей](/media/telegram-cloud-document-2-5291759145895103565.jpg)

Пример Wrapper поверхностей.

## Динамические поверхности

Динамические поверхности wrapper и control отличаются от статических поверхностей, тем что у них есть состояние surfaceState: hover, focus, disabled, active, loading и dragged. При изменении состояния, например при взаимодействии мышкой поверхность отвечает цветовой реакцией. Состояния hover, focus, disabled, active обрабатываются по дефолту и нативно браузером через компоненты RtFrame.

Это значит, что например при ховере поверхность автоматически раскрасится в другой цвет, также текст и иконки на этой поверхности тоже.

## onSurface

На каждой поверхности могут находятся символы, их цветовой токен называется с пристовкой `--on*`:

`onfoundation`, `oncontrol`, `onwrapper`

Есть две спецификации этого токена `main` и `variant`

![Спецификации main и variant](</media/image%20(8).png>)

Например здесь Label и иконки — main, а Default — variant.

Спецификация нужна, чтобы выделить цветом акцентность символа.

Их токены в ДС называются `--oncontrol-main` или `--onfoundation-variant` и тд.

Данный токен onSurface создается в контексте поверхности, это значит что он полностью зависит от цветовых абстракций самой поверхности и наследует свой цвет от поверхности.

## Создание поверхности

Поверхность создается через свойство `surface` компонента `RtFrame`.

```jsx
<RtFrame surface="foundation-low-tint">
  <RtText typography="symbol-sm-primary">Label</RtText>
  <RtText typography="symbol-sm-primary" specification="variant">
    Sublabel
  </RtText>
</RtFrame>
```

При создании поверхности создаются динамческие токены, которые зависят от цветовых абстракций и состояния поверхности, которые используются для раскраски RtText. Поэтому тексту нельзя установить какой либо токен, он всегда динамически наследуется от поверхности на которой лежит.

```css
--v0-rt-surface-color       /* Цвет поверхности */
--v0-rt-symbol-color-main   /* Цвет на поверхности main */
--v0-rt-symbol-color-variant /* Цвет поверхности variant */
```

Вся верстка в приложении по правилам дизайн системы реализуется только через компоненты `RtFrame` и `RtText`.
